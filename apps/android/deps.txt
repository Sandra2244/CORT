# Dependencias que el build del APK descarga y verifica antes de meterlas dentro.
#
# Formato: nombre | sha256 | url  (separado por barra vertical, sin espacios de más)
#
# Por qué están fijadas aquí y no "al último":
#
# * El oído de CORT es código de terceros (`libvosk.so`) más un modelo de lenguaje
#   (39,8 MB). Ninguno de los dos se escribe en este repo, y tampoco se baja "el
#   que haya ahora": se baja el que está nombrado, se le calcula la suma y, si no
#   coincide, el build se cae. Es la regla de la dueña sobre instaladores y
#   archivos ajenos aplicada a un pipeline: se lee primero, se usa después.
# * Las dos primeras vienen de Maven Central, que publica sus propias sumas
#   (`.aar.sha256` / `.aar.sha1`) y con ellas se comprobaron las que van abajo.
# * La suma del modelo es la de la copia que ya estaba dentro del APK
#   `CORT-IA-2.11.0-nucleo.apk` de la dueña — la que ella probó y le gustó — y
#   se volvió a comprobar contra el zip oficial de alphacephei.com.
#
# Licencias: Vosk y sus modelos pequeños son Apache-2.0 (LICENSE dentro del AAR
# y README de los modelos); JNA es LGPL-2.1 / Apache-2.0 doble. Se acreditan en
# `apps/android/ACREDITACION.md`, que se sube junto al APK.
#
# `zxing-core-3.5.3.jar` es el decodificador del QR del enlace (F14b). Se leyó antes
# de fijarlo: 332 entradas, todas `.class` de Java —ni una `.so`, ni un recurso, ni un
# `META-INF/services`—; el propio manifest del jar declara Apache-2.0 y exige JavaSE 1.8,
# así que entra por `javac --release 11` y por `d8` sin más. La comprobación no quedó en
# la palabra: la `.sha1` que publica Maven Central para ese archivo (ca13492…a9c4b) es la
# de la copia descargada, y la `.sha256` de abajo es la de esa misma copia.
